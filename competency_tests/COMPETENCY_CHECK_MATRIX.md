# Competency test -> check matrix

Generated by `build_check_matrix.py`. One row per (competency test, check) pair: which check answers each competency test, what that check is according to the registry, and -- as a footnote on each row -- the command that produces it.

- **31 competency tests**, answered by **38 distinct checks** across **41 rows**
- Titles, severities and categories come from `results/merged-registry.json` -- the suite's shipped registry plus this repo's own `CMP-*` entries
- *Fired* is from the last recorded run (`results/findings.csv`)

Commands run from the repo root. Set these once and every footnote is copy-pasteable as written:

```bash
M=competency_tests/fixtures/model
O=competency_tests/results/triplified
R=competency_tests/results/merged-registry.json
C=competency_tests/checks/sparql
```

### Source -- where the check comes from

`ontology-quality-suite` does not answer every test on its own, so a row's *Source* says what has to exist for its check to be reported at all. COMPETENCY_COVERAGE.md's "How it is checked" column uses the same words.

| Source | Meaning |
|---|---|
| `registry` | a check shipped in the suite's own registry, reported by a stock CLI run |
| `project-check` | a project-local `CMP-*` SPARQL check in `checks/sparql/`, loaded through the suite's documented `--registry` + `--sparql` extension points rather than by forking it |
| `suite-module` | structured output of a suite module that carries no registry id -- `consistency` rename detection, `pattern-consistency` taxonomy findings, the `version-diff` semver verdict |
| `harness` | Python in this folder -- `review_aids.py`, `mapping_integrity.py` -- for the questions that compare two artefacts, which no check over a single graph can express |

### Run -- which pass produced it

A *Run* is one pass over the fixtures, named so a finding can be traced back to the command that produced it -- the footnote on each row. The same keys label the per-run finding lists in COMPETENCY_COVERAGE.md. Several checks answer a test only in a particular run: `CNF-001` means nothing in `sketch`, where the mappings and the ontology still agree, and everything in `sketch-v2`, where they no longer do.

| Run | What it is asked of | Produced by |
|---|---|---|
| `sketch` | Query source and shape vs ontology 1.0.0 | `ontology-quality-suite sketch` |
| `sketch-v2` | Query shape vs ontology 2.0.0, which the mappings were never updated for | `ontology-quality-suite sketch`, against the newer ontology |
| `data` | Triplified output vs ontology 1.0.0 | `ontology-quality-suite data` |
| `completeness` | Documentation completeness of an authored ontology | `ontology-quality-suite checks` |
| `project-output` | Project-local checks over output + model | `ontology-quality-suite data` with `--registry` + `--sparql` |
| `project-sketch` | Project-local checks over the CONSTRUCT-template sketch | `run_competency_checks.py` (no single-command form -- see the note) |
| `pattern-consistency` | Taxonomy boundaries, in query text and in real output | `ontology-quality-suite pattern-consistency` |
| `consistency` | Ontology 1.0.0 -> 2.0.0 vs the mappings | `ontology-quality-suite consistency` |
| `version-diff` | Semver bump implied by the ontology change | `ontology-quality-suite version-diff` |
| `mapping-integrity` | Source records and defined mappings vs real output | `mapping_integrity.py` in this folder |
| `iri-pattern` | Instance IRI patterns in the mappings vs the shared core model | `run_competency_checks.py` (no single-command form -- see the note) |
| `review-aids` | Baseline output vs candidate output | `review_aids.py` in this folder |

## By competency test

The same thing read the other way: everything one test needs, in one place.

**CT-1 -- IRI generated by TARQL does not match the taxonomy/ontology concept IRI**  
Check that IRIs constructed in TARQL BIND statements exactly match the corresponding IRIs declared in the taxonomy/ontology. Identify namespace, path, casing and identifier-pattern differences.  
*Checks:* `TQL-001` &middot; *Run:* `sketch`

```bash
uv run ontology-quality-suite sketch \
  --queries competency_tests/fixtures/model/queries --file-pattern "**/*.rq" \
  --ontology competency_tests/fixtures/model/ontology/water-v1.ttl \
  --out-dir out/ct/sketch
```

**CT-2 -- Same IRI used for different concepts**  
Identify cases where separate layers or datasets generate the same IRI for concepts with different meanings. Surface repeated construction patterns and their class or graph contexts for review.
